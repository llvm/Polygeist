# lib_v3 — specifications from OpenBLAS source

lib_v3 is a second, independent spec suite. lib_v2 takes library semantics from
the netlib reference BLAS/LAPACK; lib_v3 takes them from the source of a real
optimised library, OpenBLAS 0.3.31 (BSD-3-Clause), using its portable C code
path: the CBLAS interface logic plus the plain-C kernels (`kernel/arm/*.c`,
`kernel/generic/*.c`). The architecture-specific assembly kernels and the
blocked level-3 drivers are not usable as specifications and are not used.

The cited source files are kept with checksums in
`~/netlib_ref/openblas-0.3.31/` (`SHA256SUMS`).

```
ref_c/<routine>.c        C transliteration (cites file + line ranges)
manifest/<routine>.json  specialisations, target CBLAS call, assumptions
raised/                  generated by build_lib_v2.py
RAISE_STATUS.md          generated
../kernel_library_v3.mlir  generated: one kernel.defn per RAISED spec
```

Build and use (the same scripts as lib_v2, selected by an environment variable):

```
POLYGEIST_SPEC_SUITE=lib_v3 scripts/correctness/lib_v2/build_lib_v2.py
POLYGEIST_SPEC_SUITE=lib_v3 scripts/correctness/lib_v2/match_v2.py IN.mlir -o OUT.mlir
POLYGEIST_SPEC_SUITE=lib_v3 scripts/correctness/lib_v2/sweep_polybench.py --out DIR
```

## Transliteration rules

* Macros are instantiated: `FLOAT` = `double`, `BLASLONG` = `long`, `blasint` = `int`.
* Increments are specialised to 1 (`inc_x = inc_y = 1`), as lib_v2's `INC_CASE 1`.
* Column-major addressing `a[i + j*lda]` (or a column pointer bumped by `lda`)
  becomes `A[j][i]` of the C99 VLA parameter `double A[][lda]`: the same
  address. This is the only change to the code's shape; loop order, loop form
  (`while` loops and their counters) and arithmetic order are verbatim.
  Why not keep the flat code and let `--delinearize-memref-accesses` (in the
  production recipe) recover the 2-D view? The pass can: with the interface's
  check written as `__builtin_assume(lda >= MAX(1, m))` it proves `i < lda`
  (see `test/polygeist-opt/delinearize-memref-accesses.mlir`, `@gemv_assume`).
  But the spec pipeline does not yet accept a 2-D view of a flat parameter:
  debufferize, the `kernel.defn` extraction and the per-call array rank of
  the ABI all expect the parameter itself to be 2-D. The flat attempt is kept
  in `comparison-systems/delin/v3_flat_attempt/`.
* Interface logic that runs before the kernel (`if (beta != ONE) SCAL_K(...)`)
  and kernels called by kernels (`AXPYU_K` inside `ger`) are inlined.
* Scalar branches (`beta == 0`, `beta == 1`, `alpha == 0`) become separate
  specs or recorded assumptions, as in lib_v2. Argument checking and quick
  returns on sizes are dropped.
* Data-dependent zero-skip guards (`if (da == 0.0) return;` with
  `da = alpha*y[j]` in `ger`) are removed and listed under `deviations`.
* Only the column-major entry is transliterated; row-major CBLAS calls are
  the same kernels with operands swapped, which the matcher finds through
  operand and index permutations.

Spec names start with `openblas_`. Lowering (`lower_v2.py`) handles only
`netlib_*` launches, so lib_v3 matches are not lowered yet.
