IMPLEMENTED
- polygeist_build.sh and kernel_match_rewrite.py use spec_match.py: imported Linalg bodies plus the generic region matcher.
- Removed handwritten computational templates, operation-specific predicates, structured recognizers, and benchmark-body self-matching.
- Applications and references share recipe.py, including delinearization and preservation of call boundaries until replacement.
- Unsupported optional raising stages retain their legal input and record the rejected pass. Unlowerable unmatched tensor views retain original Affine IR and count as zero matches.
- Reference import records compiler/source/artifact hashes and separate numerical checks of Affine, memref-Linalg, and debufferized stages. Only independently validated semantic stages are available to the generic matcher.
- Failed tensor stages remain excluded. Earlier valid Affine stages recover SYMM and TRMM through generic matching, without special recognizers.
- Cast operations retain their types. Unsupported scalar operations are rejected instead of becoming wildcards. Narrowing index conversions require a range proof.
- Added shared subview/reinterpret_cast handling and log1p/expm1 support. Basic views are supported; arbitrary layouts and parametric index products are not yet generally supported.
- Strict scalar matching is the default. Relaxed mode explicitly permits real-arithmetic identities and reduction reassociation. It is not a bitwise floating-point guarantee or an automatic approximation-error proof.
- Generic relaxed rules can contract a common coefficient and combine sums with identical binders and bounds. These recover SYR2K; different-range sums are rejected.
- Layout metadata only proposes bindings: the target reference body must prove the transformation, and the final target must pass backend filtering.
- Match reports pin IR, matcher/configuration, import inputs, runtime templates, and resolved vendor ABI declarations; resume requires matching evidence.
- Mechanical ABI lowering reaches actual OpenBLAS CPU calls or cuBLAS/cuSOLVER CUDA bindings. Generated runtime adapters stay in build directories.
